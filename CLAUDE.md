# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

GeoStampCamera — SwiftUI iOS app (iOS 16+, iPhone only, portrait) that captures photos/videos and burns a date/time + geolocation stamp into them, then saves the result to the Photos library. No third-party dependencies.

## Commands

The Xcode project is generated by XcodeGen from `project.yml` — `GeoStampCamera.xcodeproj` is a build artifact. Never edit the `.xcodeproj` directly; change `project.yml` and regenerate.

```bash
xcodegen generate                       # regenerate project after editing project.yml or adding/removing files

# Build for device without signing (CI-style check)
xcodebuild -project GeoStampCamera.xcodeproj -scheme GeoStampCamera \
  -sdk iphoneos -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build

# Fast typecheck without generating the project
xcrun -sdk iphoneos swiftc -typecheck -target arm64-apple-ios16.0 $(find GeoStampCamera -name '*.swift')
```

There are no tests or linter configured. Camera capture only works on a real device (simulator has no camera).

## Configuration

- Info.plist is generated (`GENERATE_INFOPLIST_FILE: YES`); privacy usage strings (camera, microphone, location, photo-library-add) live as `INFOPLIST_KEY_*` settings in `project.yml`.
- Bundle ID: `com.iamkabulov.GeoStampCamera`. `DEVELOPMENT_TEAM` is not set — add it to `project.yml` to avoid re-selecting the team in Xcode after each regeneration.

## Architecture

Data flow for a capture:

1. `CameraView` owns `CameraService` and `LocationService` as `@StateObject`s and injects `camera.locationLinesProvider`, a closure that reads `LocationService.overlayLines`. This is the only coupling between camera and location — `CameraService` does not know about CoreLocation.
2. At the moment of capture (shutter tap / record start), `CameraService` snapshots the date and location lines, so the stamp reflects capture time, not processing time.
3. `StampRenderer` (stateless enum) produces the stamped output:
   - **Photo**: `UIGraphicsImageRenderer` draws text onto the `UIImage` (orientation handled by `UIImage.draw`).
   - **Video**: after recording finishes, the `.mov` is re-exported via `AVAssetExportSession` with an `AVVideoComposition` + `AVVideoCompositionCoreAnimationTool`. The ticking clock is implemented as one `CATextLayer` per second of video, each made visible by an opacity animation at its `beginTime`. Core Animation layers here use a bottom-left origin. Location on video is fixed at record start.
4. `CameraService` saves to Photos (`.addOnly` authorization) and deletes temp files.

Threading: `AVCaptureSession` work runs on `CameraService.sessionQueue`; `@Published` state is mutated on the main actor. `LocationService` is `@MainActor`, with `nonisolated` delegate callbacks hopping back to main. The on-screen preview stamp in `CameraView` uses `StampRenderer.lines` + a 1-second `TimelineView`, so preview and burned-in text share formatting.

UI strings and comments are in Russian.

## Release Notes Generator

### Role

You are a release notes generator for the development team. You receive a list of merged pull requests for a sprint and produce a draft of release notes grouped by category — never a final publish.

### Rules

- Group entries into three categories: Features, Fixes, Improvements
- Write each entry in one sentence from the user's perspective
- Skip any PR tagged as `chore`, `internal`, or `deps`
- If a PR description is missing, use only the PR title — do not invent details
- If a PR is ambiguous, place it in Improvements and add a note for the reviewer

### Output format

Produce a Markdown document with three H2 sections: `## Features`, `## Fixes`, `## Improvements`.

Each entry is a single bullet: `- [PR title rewritten as user-facing text]`.

Append a `## Review notes` section at the end for any flagged entries. Do not include PR numbers, author names, or internal ticket IDs.

### Guardrails

- Never publish release notes to any external system without explicit user approval
- After generating the complete draft, present it to the user and ask for explicit approval before taking any further action
- Never generate entry text that is not directly derived from a PR title or description — do not invent features
- If the input PR list is empty, stop and report: "No merged PRs found"
- Stop after 2 drafting passes and present the best output with a note on what is incomplete

**Human-in-the-loop:** the trigger is the guardrail "After generating the complete draft, present it to the user and ask for explicit approval before taking any further action." Always stop at this point and wait for the user's approval.
